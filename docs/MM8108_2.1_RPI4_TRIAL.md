# RPi4 MM8108 USB 2.1 trial

Experimental, hardware validation pending. This trial produces only the RPi4
MM8108 USB image. It does not update MM6108 SDIO/SPI or publish a shared feed.
Use a separate SD card and retain the complete known-working image.

## Source contract

| Component | Revision |
| --- | --- |
| Firmware baseline | `c0f0ba46375c4ed93be416521d4a7f8730440481` |
| Packages baseline | `4736e44791166e3252ddbc4f050a784b8b5ab062` |
| 2.1 driver (annotated tag peeled commit) | `4ce0a0272f8ac8e2fa58eea8ff08116e493399de` |
| 2.1 chip firmware (annotated tag peeled commit) | `919f27a6dc2d46a988682d6ff64dd3fdb9ffc465` |

Both implementation repositories use branch `codex/mm8108-2.1-rpi4-trial`.
Record their full implementation commit IDs with every build. All other feed
pins remain in `feeds.conf.default`. The trial setup creates a local `feeds.conf`
cloning the exact commit in `scripts/mm8108-trial/packages.rev` from the matching packages checkout; it never edits default feed pins.
The trial configure script first resolves the normal board fragments, then
omits optional `m` package roots that are not in this device's package list.
Installed (`y`) defaults remain unchanged; Kconfig reselects dependencies of
retained per-device packages. This avoids building the optional package
repository while preserving fragment precedence. Baseline setup is unchanged.

`kmod-mm8108-trial` and `kmod-dot11ah-mm8108-trial` build together from the
same 2.1 source. They do not provide the baseline `kmod-dot11ah` name. The
trial driver supplies virtual `kmod-morse` for existing userspace. Conflict
metadata and the configuration gate exclude the baseline drivers/shim.
SDIO and SPI are explicitly disabled in the trial driver make arguments.
Baseline radio packages, board configurations and image definitions are retained.
Six unchanged-version userspace packages route their shim dependency through
`OPENMANET_MM8108_TRIAL`, which defaults off; normal dependency selection is unchanged.
These six packages gain a `.trial1` release suffix only when the trial switch
is enabled; upstream source versions and normal release numbers stay unchanged.

`mm8108-trial-firmware` installs only `mm8108b2-rl.bin` from 2.1. The local M20
US BCF and 0808 symlink remain unchanged. Generic BCF ownership stays with the
pinned `morse-board-config`. No upstream 2.1 BCFs or MM6108 firmware are copied.
Validate the physical adapter's BCF/calibration before RF comparisons.

Existing 2.0 morsecli, hostapd_s1g, wpa_supplicant_s1g and smart_manager stay
pinned: command compatibility with driver API 57.13 is a test requirement,
not a claim of verified compatibility. Do not blanket-update the shared feed.

Two upstreamed SPI/TX queue patches are omitted only in the trial. Regulatory,
AP/STA, VIF and boolean fixes remain. Patch 016 recognizes successful upstream
MX→US and AR/CL/CO→AU BCF fallback matches, but retains discovery-only behavior
and denies interface creation for an unsupported region.

## Reproduce on Linux

Use fresh firmware and packages checkouts at the recorded implementation commits.
Install the build prerequisites listed in the main README, plus `squashfs-tools`
for the final rootfs inspection. From firmware:

```sh
./scripts/mm8108-trial/setup.sh /absolute/path/to/trial-packages
# Public baseline submodules use SSH URLs; use HTTPS for this shell only.
export GIT_CONFIG_COUNT=1
export GIT_CONFIG_KEY_0=url.https://github.com/.insteadOf
export GIT_CONFIG_VALUE_0=git@github.com:
make download -j4
python3 scripts/mm8108-trial/check-config.py
make -j4 V=s 2>&1 | tee trial-build.log
```

Preserve the build command's exit status (`set -o pipefail` in Bash). An existing
compatible external toolchain may be selected with OpenWrt's ext-toolchain
script, but record this deviation and its config. Never share writable build or
staging directories between baseline and trial builds.

After successful image assembly, run the artifact check and capture evidence:

```sh
python3 scripts/mm8108-trial/check-artifacts.py bin/targets/bcm27xx/bcm2711
python3 scripts/mm8108-trial/check-rootfs.py bin/targets/bcm27xx/bcm2711/*sysupgrade.img.gz
mkdir -p trial-evidence
cp .config feeds.conf trial-evidence/
./scripts/diffconfig.sh > trial-evidence/diffconfig
./scripts/feeds list -s > trial-evidence/feeds.txt
git rev-parse HEAD > trial-evidence/firmware-commit.txt
git -C /absolute/path/to/trial-packages rev-parse HEAD > trial-evidence/packages-commit.txt
cp bin/targets/bcm27xx/bcm2711/*buildinfo trial-evidence/
cp bin/targets/bcm27xx/bcm2711/*.manifest trial-evidence/
sha256sum bin/targets/bcm27xx/bcm2711/*.img.gz > trial-evidence/image-sha256.txt
```

Inspect the rootfs for one `morse.ko`, one `dot11ah.ko`, no `mm6108_sdio.ko`,
matching module versions, no duplicate autoload entries, and exactly one owner
per firmware/BCF path. Do not distribute trial IPKs through production opkg feeds.

## Rollback baseline

For a matched 2.0 A/B build, use separate clean checkouts at the baseline commits
above, leave default feeds pinned, and run `openmanet_setup.sh -i -b ekh-bcm2711`,
`make download`, then `make -j4`. Retain the RPi4 MM8108 USB image plus its manifest,
config, feed revisions and SHA256. Baseline multi-profile setup may build MM6108
artifacts too; none contains the experimental shim.

A preserved pre-existing builder image is a rollback candidate, not proof of an
exact matched A/B baseline or bootability. Confirm its manifest and successful
boot on the same hardware before trial use. Save device configuration and any
adapter-specific BCF/calibration separately. Restore the complete known-working
SD image/card on failure; never roll back only the driver, shim or chip firmware.
No flashing is performed by the build scripts.

## Hardware validation procedure

Use the same RPi4, USB adapter, power supply, antenna, channel/bandwidth, country,
TX power, placement and workload for 2.0 → 2.1 → 2.0 comparisons. Keep configs
identical and record firmware image SHA256, module/firmware versions, BCF hashes,
peer versions, temperatures, RSSI/MCS, timestamps and test commands. Use wired
management and a spare recovery SD card. First establish a known-good baseline.

1. Boot and telemetry: ten cold starts, ten reboots and ten radio restarts.
   Check `dmesg`, `logread`, `iw phy`, `iw dev`, module list, interface count,
   morsecli responses, LuCI and management telemetry. Confirm valid-country
   interface creation; unsupported-country discovery must not permit RF use.
2. USB recovery: repeat controlled unplug/replug cycles and radio restart under
   idle and traffic load. Record recovery time and whether manual intervention
   is needed. Watch disconnect/recovery locks, persistent TX stalls, firmware
   restart counters, duplicate VIFs and lost telemetry.
3. Encrypted mesh: establish two-node and three-node multi-hop paths. Test trial
   peers against trial MM8108, baseline 2.0 MM8108 and unchanged MM6108 nodes.
   Include reconnect, route changes and a peer disappearing during traffic.
4. Traffic: run at least five equal-duration TCP trials in each direction,
   then bidirectional traffic. Run UDP at identical stepped offered rates,
   recording delivered rate, loss and jitter. Measure unloaded and loaded ping
   latency (median/p95/p99). Keep raw iperf3 JSON and ping logs per run.
5. ATAK: exercise real CoT/multicast with fixed event rates across one and two
   hops. Measure event delivery, duplicates and latency, including simultaneous
   unicast load. Verify service discovery and telemetry remain usable.
6. AP/STA: if used, exercise channel changes, AP/STA switching, reconnect and
   concurrent mesh behavior. Verify that existing userspace commands still work.
7. Soak: 24–48 hours with representative encrypted mesh, periodic multicast,
   bidirectional traffic and telemetry. Capture logs continuously to a wired
   host and periodically record driver statistics, memory and temperature.

Reject on any new crash, persistent TX stall, spontaneous firmware restart,
duplicate VIF or telemetry loss. Investigate any repeatable >10% throughput or
loaded-latency regression using identical conditions and repeat A/B/A runs.
Record baseline variability; a noisy single result is not a pass or failure.
Any command/API incompatibility blocks promotion. Preserve logs, restore the
complete baseline image and verify recovery after a failure. Hardware acceptance
requires actual device results; compile success alone does not satisfy it.

## Baseline observations

Resolving the existing `ekh-bcm2711` multi-profile config selects the original
MM6108/MM8108 drivers and baseline shim, with the trial switch/modules disabled.
The existing `mm6108-firmware` package conflicts with `mm8108-firmware`, so
Kconfig demotes the former to `m` despite the board requesting `y`. This trial
does not change that baseline policy; check each baseline image's actual rootfs
before treating it as a rollback artifact. The isolated trial selects neither
baseline chip firmware package.

The pinned feed set also reports an existing OpenVLM/ALSA/sound-core Kconfig
recursion during configuration. The trial configuration gate still passes;
record this warning separately from radio compilation and hardware results.

### Example measurement session

Use the same commands and offered rates on each image. On the wired test sink,
run `iperf3 -s`; use its mesh-reachable address below. The default image ships
iperf2, so these examples require the same iperf3 version installed on both A/B
images as a bench prerequisite. Alternatively, place iperf3 clients/servers on
wired endpoint hosts and measure forwarding through the mesh. On the node under
test after installing that test tool:

```sh
PEER=10.0.0.2                 # replace with the actual peer/sink mesh IP
RUN=/tmp/mm8108-ab
mkdir -p "$RUN"
uname -a > "$RUN/kernel.txt"
opkg list-installed > "$RUN/packages.txt"
lsmod > "$RUN/modules.txt"
iw dev > "$RUN/interfaces.txt"
iw phy > "$RUN/phys.txt"
batctl o > "$RUN/mesh-originators.txt"
logread > "$RUN/logread-before.txt"
dmesg > "$RUN/dmesg-before.txt"
sha256sum /lib/firmware/morse/mm8108b2-rl.bin \
  /lib/firmware/morse/bcf_mm8108_m20_us.bin > "$RUN/radio-files.sha256"
for n in 1 2 3 4 5; do
  ping -i 0.2 -c 350 "$PEER" > "$RUN/loaded-ping-$n.txt" &
  pinger=$!
  iperf3 -c "$PEER" -t 60 -O 5 -J > "$RUN/tcp-forward-$n.json"
  wait "$pinger"
  iperf3 -c "$PEER" -t 60 -O 5 -R -J > "$RUN/tcp-reverse-$n.json"
done
for rate in 1M 2M 4M; do
  iperf3 -c "$PEER" -u -b "$rate" -t 60 -J > "$RUN/udp-$rate.json"
done
logread > "$RUN/logread-after.txt"
dmesg > "$RUN/dmesg-after.txt"
```

Adjust the UDP rate ladder to the baseline link capacity and keep it fixed for
A/B. Capture bidirectional load with independent forward/reverse clients on
different server ports. Run loaded latency during both directions and multi-hop,
not just the example forward run. Export `/tmp/mm8108-ab` to the wired collector
before reboot; RAM logs disappear. Stream `logread -f` to the collector during
restart/recovery/soak tests. Annotate intentional resets so they can be separated
from spontaneous firmware restarts. Use the existing workspace mesh-testing
scripts only after reviewing their interface/IP assumptions and disruptive
operations for the particular bench. Record ATAK event counts at both sender
and receiver; iperf unicast results cannot substitute for multicast validation.
